## 3. ユーザーが決めたこと(設計判断)と理由

- **勝てない敵に対する動き**: 「1つ前の攻略済のセクションに移動する。ない場合、一番最初のセクションに戻る」+「待機中は戦闘経験値を少しずつ得る」。私の推奨は「挑まずその場で待機」だったが、ユーザーは退避先へ移動する案を自由記述で選んだ(推奨をそのまま選ぶとは限らない)。
- **イベントのスタイル**: 「ボス戦は赤ベース、通常進行は青ベース」という例示から始まり、種別6つとその配色を提案 → 「上記で実装してみてください」。ボスの基準は「セクション最強の戦闘」(29フロア)にした。
- **パーティ詳細**: 「2画面に分ける」か「タブ」かをユーザーが挙げ、タブを選んだ(操作の行き来が多く、画面遷移より軽いため)。
- **休養中の表示**: 文字/エフェクト/ボーダーのどれかを聞かれ、暗転+枠+バッジの組み合わせにした(40pxのアイコンに文字は収まらない・アイコンは毎日作り直すのでアニメーションが途切れる)。

## 4. 調査で分かったこと(原因)

- **推奨戦力の見出しが細い**: セクション枠の高さは同じで、見出しボタンが「推奨戦力あり=2行/なし=1行」だった。末尾の改行だけでは空の行を数えないので、全角スペースの2行目で高さを揃えた。
- **日本語が右に突き抜ける**: Androidの端末ビルドには日本語の分かち書きデータが無く、`AUTOWRAP_WORD`だと文全体が1語扱いで折り返されない(デスクトップは折り返せる)。
- **「先へ進む」が効かない**: 再配置が`_check_section_cleared`の中(セクションを初めて攻略した瞬間だけ、報酬受取済みなら冒頭でreturn)にしか無かった。
- **勝てない敵に全滅し続ける**: 戦闘に乱数が無く、同じ戦力なら結果は毎回同じ。休養が明けた日に、回復と再挑戦が同じ日の処理で連続するため、画面ではずっとHP1に見えた。1つのゲートで全滅すると、そのセクションの他のフロアの挑戦も止まる。
- **イベントの規模**: 194フロア中83フロアに会話がある(戦闘35・技能27・アイテム18・血筋3)。戦闘36のうち、セクション最強は29、報酬アイテム持ちは17。会話の最長は約40字(会話が長くて突き抜けたのは、チュートリアルなど長い文)。
- **端末(moto g05)**: 1604x720、切り欠きは横向きで左辺の中央(x0〜70、y336〜384)。OSは角丸半径を0と報告する(実際の角は隠れる可能性があるので24pxを固定で確保)。

## 5. 手法と落とし穴(次にやる人向け)

1. **`AUTOWRAP_WORD`は日本語のラベルに使わない**(`AUTOWRAP_WORD_SMART`にする)。デスクトップでは気付けないので、実機で長文を流して確認する。
2. **`Button`は末尾の空の行を数えない**。高さを揃えたい時は空白文字を入れる。
3. **コンテナの最小サイズはキャッシュで古くなる**(テーマやテキストの設定のタイミングで)。高さの調整は、コンテナ全体の`get_combined_minimum_size()`ではなく、各行の`get_minimum_size()`+ラベルの高さ+間隔から直接足して求める(再計算しても同じ値になるので、`minimum_size_changed`から呼んでも収束する)。
4. **`--script`でのシミュレーション**(実セーブに触れない使い捨てテスト): `APPDATA`を別ディレクトリにして`godot --headless --path godot --script <絶対パス>`。autoloadはコンパイル時の名前では使えず、`root.get_node("Name")`(絶対パスは不可)で取る。テスト本体は**最初の`_process`で走らせる**(`_initialize`ではまだautoloadの`_ready`前で、世界が空)。`class_name`のもの(`SkillTypes`等)はそのまま使える。実例: `tools/dev/`。
5. **テストのデータは実際のゲームに合わせる**: 発見済みの範囲を実際より広く設定すると(例: ボスの先の宝物庫まで発見済み)、退避のような条件判定が別の理由で動かない。
6. **一時的な診断コード**: `main.gd`をバックアップ→診断を足す→撮る/流す→Pythonで診断ブロックだけ削除→**md5がバックアップと一致することを確認**→`grep`で最新の本実装の目印が残っていることも確認。`sed -i`や`cp`で戻すと、その間の本実装を消す事故が起きる(過去に2回)。
7. **Editツールは、ファイルをLFに書き換えることがある**(Gitはautocrlf=trueで警告を出すだけで、コミットは問題ない)。改行が混ざって差分が全行になった時は`diff --strip-trailing-cr`で内容の差を見る。
8. **実機の検証**(`docs/HANDOFF.md`の「Androidビルド」も参照): ビルド→`adb install -r`(署名が同じなら上書き、スマホのセーブは残る)→起動。**インストールのたびにゲームは再起動し、新規開始(初期パーティ付き)になる**。タップは前面のアプリがゲームか確認してから(`gtap.sh`)。ポップアップは「閉じる」ボタンのタップで閉じる(戻るキーは使わない)。スクリーンショットは`adb exec-out screencap -p`、複数枚は`PIL`で1枚にまとめると見やすい。
9. **署名キーの切り替え(このセッションの最後)**: 実機のAPKは使い捨てキー(`test-release.keystore`)で署名されていた。ユーザーの選択で**本物のリリース鍵(`C:\Users\thero\worldseeker-signing\`)に切り替えた**: 署名不一致で上書きできないことを確認 → 一度アンインストール(スマホ内のセーブは消えた) → 本物のキーで署名したAPKを入れた(署名者のSHA-256が`54:D1:BF:C7…:36:1B`と一致することを`apksigner`で確認)。以後は、CIが作るAPKとも、ローカルのビルドとも、`adb install -r`で上書きできる(セーブが残る)。使い捨てキーは、もう使わない。
10. **実機ビルドの手順を、リポジトリから直接エクスポートする方式にした**(`tools/dev/android/run_on_phone.sh`、引数なしで動く)。以前は`scratchpad`(Temp)内のプロジェクトの複製(`ci/godot`)に`scripts/*.gd`だけを同期して作っていたので、`project.godot`・シーン・アセット・`licenses/`の変更が実機に載らなかった。今は作業ツリーの内容がそのまま載る(別セッションの未コミットの変更も含む)。ビルド道具(adb・JDK・Android SDK・Godotのエディタ設定とエクスポートテンプレート、合計約630MB)は、最初はTemp配下にあったが、**`D:\DevTools\godot-android`(恒久)へ移した**(`D:\Repos`はGitリポジトリ専用の整理を保ち、他のGodotプロジェクトとも共用できるよう、リポジトリの外の道具用フォルダにした)。移す時に、エディタ設定(`editor_settings-4.7.tres`)の`java_sdk_path`/`android_sdk_path`/`debug_keystore`にTempの絶対パスが入っていたので直した。移した後、そのフォルダだけで、ビルド・署名・上書きインストールが通ることを確認した(エクスポートのログにTempのパスは出ない)。古いTemp側は、消して構わない。
