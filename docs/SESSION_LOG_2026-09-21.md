## 4. 調査で分かったこと(原因)

- 既存の`world_schema_db.gd`(内容ハッシュ版管理、スロットが自分のバージョンを記録)は、「シナリオのスナップショット」にそのまま拡張できた。会話をスナップショットに含めたことで、**エディタで直しても、既存スロットは遊び始めた時点の内容のまま**になる(設計の利点であり、「エディタで直したのにゲームで変わらない」と思われやすい点)。
- ゲームは、フロアの会話の**終わりの結果コード(`pass`)で突破を確定する**(`_finalize_discovery(outcome == "pass")`)。フロアの会話が`pass`/`fail`で終わらないと、突破が確定しない。エディタの検証で検出する。
- ゲームのデータは全ての行に`next: i+1`を明示していた。行の挿入・並べ替えで「一覧の並び=会話の流れ」を保つには、編集前に、これを省略に直す必要があった。
- 案内会話の導入・前編は、起動直後にしか流れなかった。起動直後は常にデフォルトシナリオなので、自作の導入が出なかった(ユーザーの指摘の後に修正)。
- Androidでも`DirAccess.open("res://scenarios")`の一覧が機能した(懸念していたが、起動ログで確認)。

## 5. 手法と落とし穴(次にやる人向け)

- **ゲーム側の確認は`--script`のシミュレーション**(`tools/dev/sim_scenario_events.gd`、`sim_scenario_ui.gd`)。**必ず隔離した`APPDATA`**。`class_name`スクリプトがautoloadを参照していると、テストから直接名前を書けない(`Identifier not found`)ので、`load("res://scripts/event_portraits.gd")`で実行時に読む。`sim_scenario_events.gd`は、途中でスクリプトエラーが出ても「失敗0件」に見えたことがあったので、最後まで走った印(`_completed`)を出す作りにした。
- **エディタの確認は3層**: (1)`logic.test.js`(実際のデフォルトシナリオを使う: 保存し直しても全170イベントが1バイトも変わらない、種別の自動判定がゲームの集計と一致、話者名のハッシュがGodotの`String.hash()`と一致) (2)`server.test.js`(一時ディレクトリで、API・画像・安全性) (3)`browser-smoke.js`(実際のEdgeをCDPで遠隔操作。スクリーンショットも撮れる)。**Playwrightは使えなかった**(MCPサーバーが接続できなかった)ので、Node 22の組み込み`WebSocket`でCDPを直接叩いた。この層が、実バグを2つ見つけた: 検証で編集中のイベント自身を「同じIDの別イベント」と誤判定、`Element.append`に配列や`null`を渡して「[object HTMLButtonElement]」「null」という文字が出た。
- **ツール層の落とし穴**: (1)bashのヒアドキュメントに長い日本語のコードを入れると解釈が崩れた(ファイルは`Write`で作る)。(2)ツールに渡すコマンド文字列の中のバックスラッシュ+`r`/`n`(`\r\n`など)が、Python/JSのソースに**実際の改行として**入ってしまった。これでテストの正規表現が壊れた。回避: `chr(92)`で組み立てる、または`Edit`ツールを使う。(3)PythonでGDScriptの置換をする時、手打ちのタブがずれて何も置換されない(`assert 出現数 == 1`で検出する)。(4)`&&`でテスト→コミットをつなぐ時、テストの出力を`grep`で絞ると、`grep`は成功するので**失敗したテストを見逃してコミットした**(`489242a`)。失敗数を判定してからコミットすること。
- **Gitの改行**: この環境は`core.autocrlf=true`。JSONを書いたときはLFで、再チェックアウトでCRLFになり得る。往復テストは、CRLFを無視して比べる。
- **スマホへのインストール**: `bash tools/dev/android/run_on_phone.sh '\[scenario\]'`(第1引数は、logcatで待つ正規表現)。インストールのたびに、ゲームは新規セッションとして再起動する。実タップは`gtap.sh`(前面がゲートの時だけ動く)。セーブ/ロード画面は(203,524)、閉じるは(1131,78)(1604x720)。**インストールで、実機に「資金300 / Day0付近」のごみスロットができていないかは、今回は確認していない**(前回は、最初のアプリ一時停止でオートセーブされ、ごみスロットができた)。実機のスロット1(資金560/Day20)は、確認時点で無事だった。

**設計判断**(ユーザーに聞かず、こちらで決めた。理由は`scenario_editor.md`)
