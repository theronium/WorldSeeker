# WorldSeeker 開発引継ぎメモ

このファイルは「次にこのプロジェクトを触るとき、何から読んでどう動かせばいいか」をまとめた引継ぎ資料です。設計思想・仕様の正本は [`docs/design.md`](design.md) にあるので、内容の矛盾があれば design.md を優先してください。このファイルはそこへの入り口・現在地の要約です。

## 1分でわかる現状

Godot 4.7 (GDScript) 製の放置系オートバトラー的探索ゲーム。`godot/` 以下がプロジェクト本体。**コアループは実際に動く状態**まで実装済みで、シミュレーションによる動作確認も繰り返し行っている（後述の「動作確認の方法」参照）。

コアループ: NPCを雇用 → 担当セクションに割り当て → 毎日自動で発見・ゲート突破・戦闘を試行 → 節目は掲示板に記録 → 月末（実時間25分/等速）に集計 → 資金を雇用/訓練/施設拡張に再配分。

現在のワールド内容は 2エリア・10セクション・45フロアのデモ規模（`godot/scripts/world_data.gd`）。設計目標の「数百ノード」にはまだ遠く、継続的な肉付けが前提。

## 動かし方

Godot 4.7 は winget 経由でインストール済み（PATHには通っていない）:

```
GODOT_EXE="/c/Users/thero/AppData/Local/Microsoft/WinGet/Packages/GodotEngine.GodotEngine_Microsoft.Winget.Source_8wekyb3d8bbwe/Godot_v4.7-stable_win64.exe"
"$GODOT_EXE" --path godot          # 通常起動(GUI)
"$GODOT_EXE" --headless --path godot --quit   # コンパイルチェックのみ(CIっぽい用途)
```

コードを変更したら、必ず上記の `--headless --quit` でエラーが出ないことを確認してから完了報告する運用にしている。

### ロジックの検証方法(実際にこのセッションで多用した手法)

UIを手でクリックする代わりに、`main.gd` の `_ready()` の最後に一時的に `_diag_simulate()` 呼び出しを足し、`TimeSystem._advance_day()` をループで直接呼んで日数を進め、`EventDialogue.advance()/.choose()` で会話を消化し、最後に `print()` で状態を確認する。確認後は必ず元のファイルに戻す(`cp scripts/main.gd /tmp/backup.gd` してから編集し、後で `cp` し直す)。実際のマウス操作でUIをテストするのは避けること — Godotウィンドウにフォーカスが無いと、合成クリックが別の無関係なウィンドウに誤って当たるリスクがある。画面を目で確認したいときは、ウィンドウをバックグラウンド起動して `PrintWindow`(`PW_RENDERFULLCONTENT`フラグ)でそのウィンドウだけをキャプチャする(全画面キャプチャは他アプリの個人情報が写り込む事故が過去にあったので厳禁)。

## アーキテクチャ概要

`godot/scripts/` に autoload シングルトンとして分割（読み込み順は `godot/project.godot` の `[autoload]` を参照。データを使う側は使われる側より後に置くのが安全）:

| ファイル | 役割 |
|---|---|
| `time_system.gd` | 日/月の進行、倍速(1x〜16x)、月末の一時停止 |
| `world_map.gd` | エリア>セクション>フロアの階層とノードグラフ、ゲート判定 |
| `items.gd` | アイテム定義とNPC所持品(最小限) |
| `world_data.gd` | ワールドの中身(コンテンツ定義)。UIから完全に独立 |
| `world_schema_db.gd` | `world_data.gd`の内容を起動のたびにSQLiteへスナップショット出力し、そこからWorldMapを再構築するインポーターも持つ(新規プレイ開始で使用) |
| `npcs.gd` | 雇用NPCの名簿、スキル/経験値、所持品、状態(探索中/回復中) |
| `wild_npcs.gd` | 野良NPC。雇用NPCと同じ実データを探索するが、ゲートは突破できない |
| `recruitment.gd` | 募集→候補提示→雇用 |
| `economy.gd` | 資金プール、各種コスト計算式 |
| `board.gd` | 掲示板。全体フィード(節目のみ)とセクション別スレッド |
| `action_log.gd` | リプレイ/観戦用の行動ログ(掲示板と同じ粒度、構造化列で記録) |
| `combat.gd` | 戦闘解決(HP・戦闘力・事前設定方針) |
| `event_dialogue.gd` | 汎用の会話ウィンドウ進行(分岐・outcome) |
| `exploration.gd` | 自動探索の日次処理。上記のほぼ全部を束ねる中心的モジュール |
| `save_system.gd` | セーブ/ロード。`addons/godot-sqlite`(GDSQLite)経由でSQLiteに保存 |

UI(表示のみ、ロジックは持たない): `scenes/main.tscn` + `scripts/main.gd`。

`godot/addons/godot-sqlite/` は[2shady4u/godot-sqlite](https://github.com/2shady4u/godot-sqlite)のGDExtension(MITライセンス)。リポジトリ肥大化を避けるため**Windows x86_64バイナリのみ**を同梱しており(debug/release両方、`bin/libgdsqlite.windows.*.dll`)、Mac/Linux/Android/iOS向けは含めていない。別OSで動かす場合は[リリースページ](https://github.com/2shady4u/godot-sqlite/releases)から該当バイナリを追加すること。

## 実装済み

- 雇用フロー(募集コスト・候補の質による雇用コスト変動)
- 担当セクション割り当てと自動探索(発見/ゲート再判定を毎日並列実行)
- ゲート4種類すべて実装: スキル(知恵/鍵開け/破壊)・戦闘・血筋・アイテム所持
- 全スキルが「使うたびに経験値」で自然成長(資金がなくても詰まりきらない)
- 戦闘: HP管理、事前設定方針(アイテム使用/撤退)、敗北しても永久ロストなし
- イベント会話ウィンドウ(VN風、分岐対応、ただしゲート結果自体はスキル値で自動判定・会話は演出専用)
- 掲示板のスレッド化(セクション別スレッド＋節目だけの全体フィード)で野良NPCノイズを分離
- 時間システム(1ヶ月=25分@1x、1x〜16x倍速)
- スキル訓練・施設拡張UI
- ワールドコンテンツとUIの分離(`world_data.gd`)、セクション単位のグリッド自動レイアウト
- セーブ/ロード(`save_system.gd`、GDSQLite、**複数セーブスロット対応**): 資金・雇用NPC名簿(血筋/スキル経験値/所持品込み)・ワールド探索進捗(発見/突破状態)・掲示板ログ・行動ログを、スロットごとに分けた`user://saves/slot_<id>.sqlite`へ日次オートセーブ+ウィンドウクローズ時保存、起動時オートロード。アクティブなスロットは`user://worldseeker_meta.cfg`で管理
- ワールドスキーマのDB出力・再構築(`world_schema_db.gd`): `world_data.gd`の内容(エリア/セクション/ノード/接続/ゲート/イベント台本)を起動のたびに`user://worldseeker_world_schema.sqlite`へスナップショット(`export_snapshot()`)。`world_data.gd`が正本の位置づけは変わらず、DBは派生キャッシュ。逆方向の`import_into_worldmap()`もあり、新規セーブスロット作成時・スロット切替時にこれでWorldMapを再構築する(スロット間で発見/突破状態が混ざらないようにするため)
- リプレイ用行動ログ(`action_log.gd`): 掲示板と同じ粒度(発見/ゲート突破/マイルストーン)を、npc_id/node_id等の構造化列付きで追記専用のSQLiteテーブルに記録。ログビューアー方式(決定論的リプレイではない)。プレイ回ごとの`run_id`をセーブデータと一緒に保存/復元
- 行動ログビューアーUI・セーブスロット管理UI(`main.gd`): 「行動ログを見る」ボタン→NPCで絞り込める専用パネル、「セーブスロット...」ボタン→スロット一覧・切替・確認ダイアログ付き新規プレイ開始ボタンの専用パネル。左パネルはボタンが増えて縦に収まらなくなったため`ScrollContainer`化した

## 未着手・既知の課題(詳細は design.md 11章)

- **セーブスロットの削除UI**: 一覧・切替・新規作成はできるが、不要なスロットを消す操作はまだない
- **ワールドスキーマ自体の複数バージョン管理**: 現状は全スロットが常に最新の`world_data.gd`を共有する設計。将来world_data.gdの内容が変わっても既存スロットが生成時点のマップ形状を保ち続けたい場合は、スロットごとにスキーマを固定する仕組みが必要
- **コンテンツのさらなる肉付け**(45フロア → 数百ノード目標)
- 経済・戦闘・野良NPC頻度などの数値は初期チューニング値。実プレイでの調整が未実施
- マルチプレイ化(設計上は想定済みだが未着手。セッション型の時間進行を常時稼働サーバーに移行する必要がある)

## 次にやると良さそうなこと

優先度順というより「どれからでも進められる」独立した候補:
1. コンテンツ追加(`world_data.gd` に `add_area`/`add_section`/`add_node`/`set_event_scripts` を呼び足すだけ)
2. 実際にGodotエディタでしばらく触ってみて、体感バランス(コスト・確率・戦闘難度)を調整する
3. セーブスロットの削除UI、またはワールドスキーマの複数バージョン管理(どちらも新規の設計判断が必要)
