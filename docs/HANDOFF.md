# WorldSeeker 開発引継ぎメモ

このファイルは「次にこのプロジェクトを触るとき、何から読んでどう動かせばいいか」をまとめた引継ぎ資料です。設計思想・仕様の正本は [`docs/design.md`](design.md) にあるので、内容の矛盾があれば design.md を優先してください。このファイルはそこへの入り口・現在地の要約です。

## 1分でわかる現状

Godot 4.7 (GDScript) 製の放置系オートバトラー的探索ゲーム。`godot/` 以下がプロジェクト本体。**コアループは実際に動く状態**まで実装済みで、シミュレーションによる動作確認も繰り返し行っている（後述の「動作確認の方法」参照）。

コアループ: NPCを雇用 → 担当セクションに割り当て → 毎日自動で発見・ゲート突破・戦闘を試行 → 節目は掲示板に記録 → 月末（実時間25分/等速）に集計 → 資金を雇用/訓練/施設拡張に再配分。

現在のワールド内容は 9エリア・39セクション・194フロアのデモ規模（`godot/scripts/world_data.gd`）。設計目標の「数百ノード」にはまだ遠く、継続的な肉付けが前提。後発エリアほど規模と難度を緩やかに引き上げる方針（詳細はdesign.md 8.1節）。

## 動かし方

Godot 4.7 は winget 経由でインストール済み（PATHには通っていない）:

```
GODOT_EXE="/c/Users/thero/AppData/Local/Microsoft/WinGet/Packages/GodotEngine.GodotEngine_Microsoft.Winget.Source_8wekyb3d8bbwe/Godot_v4.7-stable_win64.exe"
"$GODOT_EXE" --path godot          # 通常起動(GUI)
"$GODOT_EXE" --headless --path godot --quit   # コンパイルチェックのみ(CIっぽい用途)
```

コードを変更したら、必ず上記の `--headless --quit` でエラーが出ないことを確認してから完了報告する運用にしている。

### ロジックの検証方法(実際にこのセッションで多用した手法)

UIを手でクリックする代わりに、`main.gd` の `_ready()` の最後に一時的に `_diag_simulate()` 呼び出しを足し、`TimeSystem._advance_day()` をループで直接呼んで日数を進め、`EventDialogue.advance()/.choose()` で会話を消化し、最後に `print()` で状態を確認する。確認後は必ず元のファイルに戻す(`cp scripts/main.gd /tmp/backup.gd` してから編集し、後で `cp` し直す)。実際のマウス操作でUIをテストするのは避けること — Godotウィンドウにフォーカスが無いと、合成クリックが別の無関係なウィンドウに誤って当たるリスクがある。画面を目で確認したいときは、ウィンドウをバックグラウンド起動して `PrintWindow`(`PW_RENDERFULLCONTENT`フラグ)でそのウィンドウだけをキャプチャする(全画面キャプチャは他アプリの個人情報が写り込む事故が過去にあったので厳禁)。

## アーキテクチャ概要

`godot/scripts/` に autoload シングルトンとして分割（読み込み順は `godot/project.godot` の `[autoload]` を参照。データを使う側は使われる側より後に置くのが安全）:

| ファイル | 役割 |
|---|---|
| `time_system.gd` | 日/月の進行、倍速(1x/10x/100x/1000x)、月末の一時停止 |
| `world_map.gd` | エリア>セクション>フロアの階層とノードグラフ、ゲート判定 |
| `items.gd` | アイテム定義とNPC所持品(最小限) |
| `world_data.gd` | ワールドの中身(コンテンツ定義)。UIから完全に独立 |
| `world_schema_db.gd` | `world_data.gd`の内容を内容ハッシュ版管理でSQLiteへスナップショット出力(バージョンごとに別ファイル)し、そこからWorldMapを再構築するインポーターも持つ |
| `npcs.gd` | 雇用NPCの名簿、スキル/経験値、所持品、状態(探索中/回復中) |
| `wild_npcs.gd` | 野良NPC。雇用NPCと同じ実データを探索するが、ゲートは突破できない |
| `recruitment.gd` | 募集→候補提示→雇用 |
| `economy.gd` | 資金プール、各種コスト計算式 |
| `board.gd` | 掲示板。全体フィード(節目のみ)とセクション別スレッド |
| `action_log.gd` | リプレイ/観戦用の行動ログ(掲示板と同じ粒度、構造化列で記録) |
| `combat.gd` | 戦闘解決(HP・戦闘力・事前設定方針) |
| `event_dialogue.gd` | 汎用の会話ウィンドウ進行(分岐・outcome) |
| `exploration.gd` | 自動探索の日次処理。上記のほぼ全部を束ねる中心的モジュール |
| `save_system.gd` | セーブ/ロード。`addons/godot-sqlite`(GDSQLite)経由でSQLiteに保存 |

UI(表示のみ、ロジックは持たない): `scenes/main.tscn` + `scripts/main.gd`。

autoloadではなく`class_name`で共有する定義専用モジュールも2つある: `skill_types.gd`(`SkillTypes`、スキル種別)、`name_generator.gd`(`NameGenerator`、血筋ごとの事前生成名前辞書)。

`godot/addons/godot-sqlite/` は[2shady4u/godot-sqlite](https://github.com/2shady4u/godot-sqlite)のGDExtension(MITライセンス)。リポジトリ肥大化を避けるため**Windows x86_64バイナリのみ**を同梱しており(debug/release両方、`bin/libgdsqlite.windows.*.dll`)、Mac/Linux/Android/iOS向けは含めていない。別OSで動かす場合は[リリースページ](https://github.com/2shady4u/godot-sqlite/releases)から該当バイナリを追加すること。

## 実装済み

- 雇用フロー(募集コスト・候補の質による雇用コスト変動)
- 担当セクション割り当てと自動探索(発見/ゲート再判定を毎日並列実行)
- ゲート4種類すべて実装: スキル(知恵/鍵開け/破壊)・戦闘・血筋・アイテム所持
- 全スキルが「使うたびに経験値」で自然成長(資金がなくても詰まりきらない)
- 戦闘: HP管理、事前設定方針(アイテム使用/撤退)、敗北しても永久ロストなし
- イベント会話ウィンドウ(VN風、分岐対応、ただしゲート結果自体はスキル値で自動判定・会話は演出専用)
- 掲示板のスレッド化(セクション別スレッド＋節目だけの全体フィード)で野良NPCノイズを分離
- 時間システム(1ヶ月=25分@1x、1x/10x/100x/1000x倍速)
- スキル訓練・施設拡張UI
- ワールドコンテンツとUIの分離(`world_data.gd`)、セクション単位のグリッド自動レイアウト
- セーブ/ロード(`save_system.gd`、GDSQLite、**複数セーブスロット対応**): 資金・雇用NPC名簿(血筋/スキル経験値/所持品込み)・ワールド探索進捗(発見/突破状態)・掲示板ログ・行動ログを、スロットごとに分けた`user://saves/slot_<id>.sqlite`へ日次オートセーブ+ウィンドウクローズ時保存、起動時オートロード。アクティブなスロットは`user://worldseeker_meta.cfg`で管理
- ワールドスキーマのDB出力・再構築(`world_schema_db.gd`): `world_data.gd`の内容(エリア/セクション/ノード/接続/ゲート/イベント台本)から正規化JSONのSHA-256を`schema_version`とし、`user://schemas/schema_<version_id>.sqlite`へバージョンごとに別ファイルで保存。`world_data.gd`が正本の位置づけは変わらず、DBは派生キャッシュ。逆方向の`import_into_worldmap(version_id)`もある
- **ワールドスキーマの複数バージョン管理**: 各セーブスロットは保存のたびに自分が実際に読み込んでいるバージョンを記録し(`meta.schema_version`)、起動時・スロット切替時は必ずそのスロット自身のバージョンで`import_into_worldmap()`し直す(新規プレイ開始は常に最新バージョン)。`world_data.gd`の内容が将来変わっても、既存スロットは自分が生成された時点のマップ形状を保ち続ける。`WorldMap.reset()`/`Items.reset()`を先に呼んでから再構築する必要がある点に注意(呼ばないと別バージョンの要素が残ってしまう不具合になる。実際に一度検出して修正した)
- リプレイ用行動ログ(`action_log.gd`): 掲示板と同じ粒度(発見/ゲート突破/マイルストーン)を、npc_id/node_id等の構造化列付きで追記専用のSQLiteテーブルに記録。ログビューアー方式(決定論的リプレイではない)。プレイ回ごとの`run_id`をセーブデータと一緒に保存/復元
- 行動ログビューアーUI・セーブスロット管理UI(`main.gd`): 「行動ログ」ボタン→NPCで絞り込める専用パネル、「セーブ」ボタン→スロット一覧・切替・削除・確認ダイアログ付き新規プレイ開始ボタンの専用パネル
- セーブスロットの削除(`SaveSystem.delete_slot()`): アクティブな(現在開いている)スロットは削除不可というガード付き。UIからも確認ダイアログ経由で削除できる
- **マップUIの刷新**(2026-09-12〜13): GraphEdit/GraphNode/GraphFrameはノードグラフ**編集**用ウィジェットで、ノード・フレームをドラッグで動かせてしまいプレイ中に意図せずレイアウトが崩れる問題があったため撤廃。素の`Control`(Panel/PanelContainer/Label、`mouse_filter = IGNORE`)による自前描画+`draw_line()`での接続線描画に置き換えた。ScrollContainerだけでは広いマップを動き回りづらいため、キャンバスの空き領域を左ドラッグしてパンできる機能を自前実装
- **サイドバーのポップアップパネル化**: 機能追加でボタンが増えて240px幅に収まらなくなったため、「雇用」「NPC管理」ボタンを新設し、募集/雇用・NPC名簿/担当割り当て/スキル訓練/施設拡張をそれぞれ専用パネルに集約(既存の行動ログ/セーブと同じ方式に統一)。4パネルは同時に開けず、開いている間は半透明の遮断レイヤーが背景全体(マップ・サイドバー含む)の操作を止める(`_open_modal`/`_close_modal`)

- **収入システム(ワーカー配置型)・NPC自動命名・マップ操作性の改善**(2026-09-13): 「資金が増えない」(=`Economy.earn()`がどこからも呼ばれておらず、design.md 6章で構想されていた収入経路が未実装のままだった)への対応として`exploration.gd`に実装。担当NPCが**現在いる**セクションの「累計突破フロア数×セクション倍率(エリアの登場順で自動算出、`WorldMap.section_multiplier()`)」を月末収入として支給し、セクション完全攻略時には一時金(初回攻略のみ追加ボーナス、`WorldMap.is_section_reward_claimed()`で二重支給を防止)を出す。NPCごとに`Npcs.PostClearBehavior`(留まる/次の未踏破セクションへ自動移動、`WorldMap.next_section_to_explore()`)を設定できる。NPCの名前は`候補N`のプレースホルダのままだったのを、`name_generator.gd`(血筋ごとに雰囲気を変えた事前生成の名前辞書。design.md 8.1の「オフライン生成」方針に合わせた)から抽選するよう修正。マップには担当NPCの頭文字アイコンをセクション枠に表示(クリックでNPC管理パネルを開く)、マップ上部にはエリア選択ボタンをフロート表示してクリックでそのエリアまでスクロールする機能を追加。セーブデータには`npcs.post_clear_behavior`列と`section_rewards`テーブルを追加(前者は既存テーブルへの`ALTER TABLE`、後者は新規テーブル)。シミュレーションで検証済み: 名前生成・月次収入・攻略報酬(初回ボーナス込み)・二重支給防止・完全攻略後の自動再配置(1体のNPCが訓練済みの状態で「小さな王国」の複数セクションを連続で攻略・自動移動していく様子まで確認)
- **上記収入システムの追加バグ修正・UI改善**(2026-09-13、同日中のフォローアップ): (1) `Economy.earn()`自体は動いていたが、`main.gd`の`_on_month_ended`/`_on_day_advanced`が`_refresh_funds()`を呼んでいなかったため、月次収入やセクション攻略の一時金が入っても資金表示(UIラベル)がその場では更新されず「資金が増えない」ように見えるバグがあった。両ハンドラに`_refresh_funds()`を追加して修正。(2) NPC管理パネルの担当セクション選択肢が、実際には到達不可能な(どこからも繋がっていない)セクションも含め全39セクションを表示していたため、選んで割り当てても何も進行せず「移動できない」ように見える問題があった。`WorldMap.is_section_reachable()`(既に到達済み、またはfrontier_for_sectionが空でない)で候補を絞り込み、到達不可能なセクション(および該当セクションが1つも無いエリアごと)は選択肢に出さないよう`_populate_section_tree()`を修正。(3) NPCの状態(探索中/回復中(あと何日)/未割当)とスキルレベルの一覧が、NPC管理パネルにもロースター一覧にも表示されておらず(特に戦闘敗北後の「回復中」はUIのどこにも出ておらず、なぜ動いていないのか分からなかった)、`_npc_status_text()`/`_npc_level_summary()`を追加してNPC詳細・ロースター一覧の両方に表示するようにした
